## Member ID: explanation to give Brian

CNCGetCaseInfo first chooses which Account field supplies the local ID. It checks Account.Record_Type__c, not LOB. When that custom field matches ITS Host or the second configured member-type literal, it selects Subscriber_Id__pc; otherwise it selects Member_Id__pc. It stores the result as localMemberId. The second literal appears to read Engen Member, but its spelling remains unverified.

Later, SV-AddressMapping sets the final memberId. If apiMemberId is neither empty nor null, it uses apiMemberId; otherwise it uses localMemberId. Both Provider and non-Provider branches do the same selection. The Apex token method then reads memberId according to the template token's mapping key and copies it into tokenMapping. It does not decide which Account field to read.

Thus the DR chooses the local source field; Set Values chooses between the API result and that local result. ITS Host LOB alone does not determine either outcome. The API token mapper also has its own claim-response-to-local fallback before outputting apiMemberId. See the canonical specification and dated investigation for the complete trace.
